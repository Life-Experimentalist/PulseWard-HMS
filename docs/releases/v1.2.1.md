# PulseWard Release 1.2.1 (In Progress)

Status: Draft snapshot for active milestone delivery

## Summary

This snapshot captures the post-1.2.0 hardening work delivered across M1 contract reliability, M2 auth/admin configurability seed, M5 provider readiness checks, and M6 admin console operational scaffold.

## Highlights

- M1.2-M1.6 completed:
  - Semantic route/spec contract parity checks.
  - Drift reconciliation across gateway, EHR, lab, and billing services.
  - Strict parity mode enabled in CI.
  - Regression tests added to prevent drift reintroduction.
  - Critical endpoint request/response schema coverage checks added for auth, booking, and notification APIs.
- Auth service enhancements (M2 seed):
  - Tenant admin settings read/write APIs.
  - Admin settings storage metadata API.
  - Google OAuth config-status endpoint.
  - ABHA config-status and gateway health-check endpoints.
- Notification service enhancements (M5 seed):
  - Telegram config-status endpoint.
  - SMTP config-status endpoint.
  - Existing provider test path supports live checks when `dryRun=false`.
- Admin console scaffold (M6 seed):
  - Production-style static runtime support.
  - Integrated service health diagnostics.
  - Integrated OAuth/ABHA/provider readiness visibility.

## API Contract Updates

- Auth OpenAPI includes admin settings and ABHA readiness routes.
- Notification OpenAPI includes Telegram and SMTP config-status routes.
- Contract parity matrix is fully reconciled with no allowlisted drift.
- Contract checker now enforces critical endpoint schema coverage in strict and standard runs.

## Operational Impact

- Teams can diagnose auth/provider/ABHA readiness without manual env inspection.
- CI now fails quickly on contract parity regressions.
- CI now also fails when critical endpoint request/response schema coverage is missing.
- Admin operators have a stable dashboard baseline for tenant routing and integration diagnostics.

## Migration Notes

1. Pull the latest `.env.example` values into deployment secret stores.
2. Validate contracts and route loading:
   - `npm run contracts:check -- --strict`
   - `npm run test:routes`
3. Validate integration config and smoke behavior:
   - `npm run integrations:validate`
   - `npm run test:smoke`
4. For ABHA checks, ensure `ABHA_GATEWAY_BASE_URL`, `ABHA_CLIENT_ID`, and `ABHA_CLIENT_SECRET` are set with real values.

## Rollback Plan

- Revert auth or notification service changes as a single slice commit where needed.
- Keep legacy integration/provider configuration entries while rolling back.
- Re-run contract and smoke checks before reopening traffic.
