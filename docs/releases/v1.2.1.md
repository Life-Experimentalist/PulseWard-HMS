# PulseWard Release 1.2.1 (In Progress)

Status: Draft snapshot for active milestone delivery

## Summary

This snapshot captures the post-1.2.0 hardening work delivered across M1 contract reliability, M2 auth/admin configurability seed, M5 provider readiness checks, and M6 admin console operational scaffold.

## Highlights

- M1.2-M1.6 completed:
  - Semantic route/spec contract parity checks.
  - Drift reconciliation across gateway, EHR, lab, and billing services.
  - Strict parity mode enabled in CI.
  - Regression tests added to prevent drift reintroduction.
  - Critical endpoint request/response schema coverage checks added for auth, booking, and notification APIs.
- Auth service enhancements (M2 seed):
  - Tenant admin settings read/write APIs.
  - Admin settings storage metadata API.
  - Google OAuth config-status endpoint.
  - ABHA config-status and gateway health-check endpoints.
- Auth policy enhancements (M2.2):
  - Tenant-level auth policy schema validation module.
  - `POST /api/v1/admin/settings/auth-policy/validate` endpoint.
  - Auth policy normalization and persistence via admin settings APIs.
  - Regression tests covering valid/invalid policy payloads and persistence.
- Auth flow enforcement enhancements (M2.3):
  - Tenant auth policy enforcement on `POST /api/v1/auth/login`.
  - Tenant auth policy guards on Google and Clerk OAuth entry/callback routes.
  - Structured policy-denial error payloads with audit event metadata.
  - Regression tests for policy allow/deny behavior in login and OAuth flows.
- Auth role/session controls (M2.4):
  - Role-provider compatibility overrides enforced per tenant policy.
  - Role-based session TTL overrides enforced in login and OAuth callback token issuance.
  - Policy-denial payloads include role-allowed provider details for operator diagnostics.
  - Regression tests added for role-compatibility and role-specific session behavior.
- OTP and MFA policy execution (M2.5):
  - Added `POST /api/v1/auth/otp/request` and `POST /api/v1/auth/otp/verify` flows.
  - Added role-targeted MFA policy support and login-time MFA enforcement.
  - Added short-lived OTP verification token path for MFA-compliant login completion.
  - Regression tests added for MFA-required login and OTP challenge lifecycle behavior.
- Workflow-entry and auth session observability (M3.1):
  - Added `POST /api/v1/auth/workflow-entry/check` to gate patient/clinical workflow entry by tenant auth policy, role compatibility, and MFA status.
  - Added `GET /api/v1/auth/session/events` for role-scoped auth outcome observability with tenant/action/outcome filtering.
  - Added auth event emission for workflow allow/deny outcomes and existing login/OAuth/OTP lifecycle checkpoints.
  - Regression tests added for workflow allow, role denial, MFA-required workflow entry, and session-event query filtering.
- Notification service enhancements (M5 seed):
  - Telegram config-status endpoint.
  - SMTP config-status endpoint.
  - Existing provider test path supports live checks when `dryRun=false`.
- Admin console scaffold (M6 seed):
  - Production-style static runtime support.
  - Integrated service health diagnostics.
  - Integrated OAuth/ABHA/provider readiness visibility.

## API Contract Updates

- Auth OpenAPI includes admin settings and ABHA readiness routes.
- Auth OpenAPI now includes tenant auth policy validation schemas and endpoint.
- Auth OpenAPI now includes policy-enforcement response semantics for login and OAuth flows.
- Auth OpenAPI now includes role/session policy fields under tenant auth policy schemas.
- Auth OpenAPI now includes OTP request/verify contracts and MFA-required login response semantics.
- Auth OpenAPI now includes workflow-entry authorization check and session observability event query contracts.
- Notification OpenAPI includes Telegram and SMTP config-status routes.
- Contract parity matrix is fully reconciled with no allowlisted drift.
- Contract checker now enforces critical endpoint schema coverage in strict and standard runs.

## Operational Impact

- Teams can diagnose auth/provider/ABHA readiness without manual env inspection.
- CI now fails quickly on contract parity regressions.
- CI now also fails when critical endpoint request/response schema coverage is missing.
- Security and operations teams can inspect role-scoped auth flow outcomes through queryable session event telemetry.
- Admin operators have a stable dashboard baseline for tenant routing and integration diagnostics.

## Migration Notes

1. Pull the latest `.env.example` values into deployment secret stores.
2. Validate contracts and route loading:
   - `npm run contracts:check -- --strict`
   - `npm run test:routes`
3. Validate integration config and smoke behavior:
   - `npm run integrations:validate`
   - `npm run test:smoke`
4. For ABHA checks, ensure `ABHA_GATEWAY_BASE_URL`, `ABHA_CLIENT_ID`, and `ABHA_CLIENT_SECRET` are set with real values.

## Rollback Plan

- Revert auth or notification service changes as a single slice commit where needed.
- Keep legacy integration/provider configuration entries while rolling back.
- Re-run contract and smoke checks before reopening traffic.
