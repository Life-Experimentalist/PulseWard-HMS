# PulseWard Release 1.2.0

Release date: 2026-04-01

## Summary

This release aligns contracts and operations for role-based auth, OAuth provider setup, tenant domain segregation, and practical deployment workflows while keeping all runtime APIs on `/api/v1`.

## Highlights

- Auth service OpenAPI updated to match implemented role login, OAuth provider discovery, and domain-config APIs.
- Notification and appointment OpenAPI versions bumped to 1.2.0 and updated with current runtime defaults.
- Integration provider contract docs aligned to implemented `/api/v1/integrations/*` endpoints.
- Added deployment and domain migration runbook for GitHub subdomain-first rollout and custom domain cutover.
- Added explicit deploy validation flow using route-load and smoke test scripts.

## API Contract Updates

- `services/auth-service/openapi.yaml` now documents:
  - `GET /auth/roles`
  - `POST /auth/register`
  - `POST /auth/login`
  - `GET /auth/oauth/providers`
  - `GET /auth/oauth/google/start`
  - `POST /auth/oauth/google/callback`
  - `GET /auth/oauth/clerk/start`
  - `GET /platform/domain-config`
  - `POST /platform/domain-config/validate`
  - `GET /platform/domain-config/all`
- `services/notification-service/openapi.yaml` includes Telegram setup endpoint and dry-run test fields.
- `services/appointment-service/openapi.yaml` updated to release version 1.2.0.

## Operational Impact

- Tenant domain segregation checks are now documented and testable before cutover.
- OAuth provider setup path is explicit for free-first (Google) and paid-optional (Clerk) login models.
- Deployment guidance supports local demo, GitHub subdomain hosting, and custom-domain migration without path changes.

## Migration Notes

1. Pull latest env additions from `.env.example` into runtime secret stores.
2. Validate tenant integration configuration:
   - `pnpm integrations:validate`
3. Validate route modules and smoke behavior:
   - `pnpm test:routes`
   - `pnpm test:smoke`
4. Update domain config and allowed origins before enabling new tenant domains.

## Rollback Plan

- Revert `config/domains/default-domain-config.json` to the last known good version.
- Keep legacy origins temporarily in `allowedOrigins` during rollback.
- Revert OpenAPI and docs references to 1.1.0 if downstream clients require strict spec parity.
- Re-run validation and smoke tests before reopening traffic.
