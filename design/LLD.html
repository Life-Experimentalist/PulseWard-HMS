1 · System context

Five client surfaces, one API contract, seven backend services, three data planes.

Trust boundary: everything to the left of the API Gateway is untrusted (any client can be impersonated). Everything to the right runs inside Cloudflare's Worker isolate and only talks to managed primitives. The gateway is the only place we need full auth + tenant + audit logic.

5 · auth-service

auth-service
Stateless · D1 + KV
:5101

Identity, credentials, sessions, 2FA, ABHA-OAuth.

Every request to any other service must carry a JWT minted here. Refresh tokens are opaque IDs whose hash lives in KV; rotation is one-shot.

Module layout

services/auth-service/ ├─ src/ │ ├─ index.ts # Hono app │ ├─ routes/ │ │ ├─ signup.ts │ │ ├─ login.ts # constant-time, rate-limited │ │ ├─ refresh.ts # single-use rotation │ │ ├─ logout.ts │ │ ├─ password.ts # reset → email link │ │ ├─ twofa.ts # TOTP enroll + verify │ │ └─ me.ts │ ├─ lib/ │ │ ├─ jwt.ts # HS256 sign + verify │ │ ├─ hash.ts # argon2id with pepper │ │ ├─ session.ts # KV refresh-token CRUD │ │ └─ ratelimit.ts # sliding window per (ip,email) │ └─ data/ │ └─ admin-console-settings.json # tenant admin prefs └─ test/

Endpoints

POST/v1/auth/signup
Create patient user. Auto-creates patients row + MRN. Issues tokens.
Schemas 
// Request
{ name: str(2,80), email: email, password: str(8,128),
  dob: "YYYY-MM-DD"?, gender: "M"|"F"|"O", phone: "+91..." }

// 201 OK
{ ok: true, token: jwt, role: "patient", user: { id, email, name }, patient: { id, mrn, profileId } }

// 409 — email_taken
// 429 — rate_limited (5 signups per IP per hour)
POST/v1/auth/login
Email + password. Returns access JWT in body, refresh in HttpOnly cookie.
Schemas 
// Request
{ email, password, tenantHint?: slug }

// 200 — token + role
{ ok: true, token, role, user, requires2fa?: true }

// 401 invalid_credentials  // 403 locked  // 429 too_many_attempts
POST/v1/auth/refresh
Rotates refresh token (one-shot). Old token is invalidated immediately.
POST/v1/auth/logout
Revokes the refresh token and all derived sessions on this device.
POST/v1/auth/password/forgot
Always returns 204; sends email with single-use reset link (15-min TTL).
POST/v1/auth/password/reset
Burns the reset token. Invalidates all existing sessions for the user.
POST/v1/auth/2fa/enroll   POST/v1/auth/2fa/verify
TOTP enrollment for clinicians/admins. Returns a QR-code URL + 8 backup codes.
GET/v1/auth/me
Returns the current user + role + tenant. Used by every app on boot.

JWT claims

{
  "iss": "pulseward",
  "sub": "<userId>",
  "tid": "<tenantId>",
  "role": "patient"|"clinician"|"admin"|"frontdesk"|"ops",
  "eid": "<linked_entity_id>",
  "sid": "<sessionId>",
  "iat": 1715900000,
  "exp": 1715900900
}
// HS256 with JWT_SECRET. 15-min lifetime. Refresh token is opaque + in KV.

Hashing

argon2id({ memoryCost: 19456, timeCost: 2, parallelism: 1 })
hash = argon2(password || PEPPER, perUserSalt)
// PEPPER is a 32-byte hex secret stored in Workers Secrets — rotated quarterly.
// Salt is 16 random bytes per user, persisted alongside hash.

Session lifecycle

anonymous → signup/login → active → access exp → refreshing → rotated → active → logout/idle 30d → revoked

If a refresh token is presented twice (reuse detection) the entire session family is killed and the user is forced to log in again.

6 · patient-service

patient-service
Per-tenant CRUD
internal

The patient record. Demographics, conditions, allergies, vitals, MRN.

Owns the canonical patients table. Reads are common; writes are clinician-only after a patient is created. Search must hit p95 < 80 ms with 100 k records.

Endpoints

GET/v1/patients?q=&limit=20&cursor=
Full-text on name | mrn | phone | abha_address. Returns paged list with opaque cursor. Tenant-scoped automatically.
GET/v1/patients/:id
Full record. Includes computed fields: age, openOrders, activeRx.
POST/v1/patients
Front-desk creates a patient. MRN auto-generated. Emits patient.created.
PATCH/v1/patients/:id
Partial update. Never overwrites the entire JSON column — merges keys server-side.
POST/v1/patients/:id/vitals
Append a vitals snapshot. Tracked separately for time-series rendering.
POST/v1/patients/:id/link-abha
Calls abha-service. Stores abha_number + abha_address on success.

MRN format

// Format: {tenant.short}-{YY}-{seq}
// Examples: PW-26-04217, MA-26-00112
// Sequence is monotonically increasing per (tenant_id, year).
mrn(tenantId) = `${tenant.short}-${yy()}-${nextSeq(tenantId)}`

Validation

  • phone normalized to E.164 before insert (+91XXXXXXXXXX).
  • dob must be a real date and not in the future.
  • bloodType is one of A+|A-|B+|B-|AB+|AB-|O+|O-|unknown.
  • allergies entries each carry a severity (mild|moderate|severe|life-threatening) — severe and above are surfaced as banners on every screen.

7 · appointment-service

appointment-service
Calendar engine
:5103

Booking, conflicts, availability, reassignment.

Most contended write surface in the system. Bookings race; we serialize per (clinician_id, day) with optimistic concurrency on the appointments index.

Endpoints

GET/v1/appointments?clinicianId=&date=YYYY-MM-DD
Day view for one clinician. Returns 100 events max.
GET/v1/appointments?patientId=&upcoming=true
Patient's upcoming + past 30-day history.
POST/v1/appointments
Book. 409 if slot is taken; 422 if patient has another appointment within 30 min.
PATCH/v1/appointments/:id
Reschedule, cancel, check-in, complete. State guarded — see FSM.
POST/v1/availability
Clinician adds a block (leave, OR slot, conference). Returns affected: [appointmentId] — those become reassignment candidates.
GET/v1/reassignments
Front-desk queue. Filter by status, sort by patient priority.
POST/v1/reassignments/:id/resolve
Body: { action: "reschedule"|"reassign"|"cancel", … }. Atomically updates the appointment and emits notifications.

Booking race protection

// services/appointment-service/src/lib/book.ts
async function book(req) {
  return db.transaction(async (tx) => {
    const conflict = await tx.prepare(`
      SELECT id FROM appointments
       WHERE tenant_id = ? AND clinician_id = ?
         AND status NOT IN ('cancelled','no-show')
         AND starts_at < ? AND starts_at + duration_min*60*1000 > ?
       LIMIT 1`).bind(t, c, req.endsAt, req.startsAt).first();
    if (conflict) throw new ConflictError('slot_taken');

    await tx.prepare('INSERT INTO appointments …').bind(…).run();
  });
}

Reassignment queue lifecycle

open → propose → proposed → confirm → resolved   or  proposed → patient declines → open

8 · ehr-service

ehr-service
Clinical record
:5104

Notes (signed = immutable), messages, attachments.

The legal record of care. Notes are append-only after signing — every later edit becomes an addendum. Hash chained for tamper evidence.

Note state machine

draft → save → draft → sign → signed → addendum → addended → sign → signed

Once signed_at is set, the row's columns are read-only. New rows reference the parent via addendum_of and store prev_hash = sha256(prev.body).

Endpoints

POST/v1/notes · PATCH/v1/notes/:id · POST/v1/notes/:id/sign
GET/v1/threads?patientId= · POST/v1/threads · POST/v1/threads/:id/messages
POST/v1/attachments
Returns presigned R2 PUT URL for the client to upload directly. We then POST /v1/attachments/:id/finalize to virus-scan + link.

Note schema (signed shape)

{
  id, tenant_id, patient_id, clinician_id,
  type: "soap"|"progress"|"telecons"|"admission"|"discharge",
  title, body: { subjective, objective, assessment, plan },
  diagnoses: [{ icd10, label }],
  signed_at, prev_hash, addendum_of?
}

abha-service

Token caching

// All ABDM-bound calls go through this helper
async function getAbdmToken(env) {
  const cached = await env.KV.get('abdm:access');
  if (cached) return cached;
  const tok = await fetchAbdmSessionToken(env);
  await env.KV.put('abdm:access', tok.access_token, { expirationTtl: 540 }); // 9-min safety on 10-min real TTL
  return tok.access_token;
}

15 · Cross-cutting concerns

Idempotency

Any mutating endpoint that can be retried by a client accepts Idempotency-Key.

// services/api-gateway/src/middleware/idempotency.ts
const key = c.req.header('Idempotency-Key');
if (key) {
  const cached = await env.KV.get(`idem:${key}`);
  if (cached) return c.json(JSON.parse(cached));
}
const res = await next();
if (key && res.ok) await env.KV.put(`idem:${key}`, JSON.stringify(res.body), { expirationTtl: 86400 });

Audit

Every write goes through audit(ctx, action, diff) before commit.

  • actor = email or service identity
  • scope = pat:<id>, appt:<id>, etc.
  • ip + user_agent captured
  • diff_json stores before/after for mutable rows
  • Daily roll-up Worker exports to R2 (cold tier)

Authorization (RBAC + tenant)

// middleware/guard.ts
function guard(roles: Role[], scope?: 'self'|'tenant'|'any') {
  return async (c, next) => {
    const u = c.get('user');
    if (!roles.includes(u.role)) return c.json({ error: 'forbidden' }, 403);
    if (scope === 'self' && c.req.param('id') !== u.eid) return c.json({ error: 'forbidden' }, 403);
    await next();
  };
}
// usage:
app.get('/v1/patients/:id', guard(['patient'], 'self'), …);
app.post('/v1/appointments', guard(['patient','frontdesk','clinician']), …);

Validation

Single source of truth for shapes lives in packages/schema. Backends validate with Zod; frontends import the same Zod schemas to drive form errors.

Observability

  • Per-request structured log line (trace_id, route, status, ms, user, tenant)
  • Sentry SDK in Workers — captures unhandled errors with sourcemaps
  • Cloudflare Analytics for traffic + edge latency
  • Custom counters via Workers Analytics Engine: notify.delivered, appt.book.conflict, abha.enrol.success
